Zero-Knowledge Cryptography & Data Isolation Specification

An in-depth technical analysis of SecuroSpace’s zero-knowledge architecture, client-side key derivation routines, threat modeling, and local-first data sovereignty on securospace.com.

Cryptographic Axiom

SecuroSpace operates under a strict Zero-Knowledge mandate: The server infrastructure never receives, processes, or stores plaintext user data, master passphrases, or unencrypted keys. Even under subpoena or total server compromise, user secrets cannot be reconstructed without client-side master keys.

1. Threat Model & Security Assumptions

Modern productivity tools collect unprecedented volumes of intimate personal intelligence: daily routines, active priorities, psychological habits, financial net worth, and digital credentials. In traditional SaaS architectures, this data sits in plaintext databases accessible to employees, rogue scripts, and legal warrants.

SecuroSpace explicitly models against the following threat vectors:

  • Untrusted / Compromised Server Infrastructure: Host machines, cloud databases, and DNS routing are assumed to be potentially hostile or audited by third parties.
  • Network Interception & Man-in-the-Middle (MITM): Traffic over the wire is guarded with TLS 1.3, HSTS, and authenticated encryption payload verification.
  • Data Leakage via Third-Party SDKs: SecuroSpace includes zero third-party telemetry, tracking pixels, ad networks, or social widgets.
  • Silent Ciphertext Tampering: Protected via Galois/Counter Mode (GCM) 128-bit authentication tags.

2. Cryptographic Primitives & Key Derivation

SecuroSpace builds upon battle-tested, standardized cryptographic primitives implemented directly in native browser Web Cryptography APIs (W3C Recommendation).

A. Master Key Derivation (PBKDF2-HMAC-SHA256)

When a user initializes their vault on securospace.com, their Master Passphrase never leaves the device. A 256-bit symmetric Master Encryption Key (MEK) is derived using Password-Based Key Derivation Function 2:

MEK = PBKDF2(PRF: HMAC-SHA256, Password: UserPassphrase, Salt: CryptographicRandomSalt_16Bytes, Iterations: 600,000, KeyLength: 256)

The 600,000 iteration threshold complies with current NIST SP 800-132 standards to defeat GPU/ASIC-based brute-force attacks.

B. Authenticated Symmetric Encryption (AES-256-GCM)

All individual records (tasks, habit streaks, ledger transactions, and credentials) are encrypted separately using Advanced Encryption Standard in Galois/Counter Mode:

  • Cipher: AES-256 (256-bit key length)
  • IV (Initialization Vector): 96-bit cryptographically secure random value generated per-record via crypto.getRandomValues(). IVs are never reused.
  • Auth Tag: 128-bit integrity authentication tag ensuring both confidentiality and authentic origin.

5. Domain Infrastructure & Network Protection

The official website and web app are delivered over https://securospace.com/ with:

  • HSTS (HTTP Strict Transport Security): Preload-ready header forcing all traffic through encrypted TLS channels.
  • DNSSEC & CAA Records: Restricting SSL certificate issuance to trusted Certificate Authorities.
  • Static Delivery: Zero dynamic backend PHP or Node scripting that could introduce remote code execution vulnerabilities.
